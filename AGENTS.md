# Publication workflow

- Honor the user-requested additive history: add a new numbered checkpoint directory and a separate commit for each meaningful analysis pass.
- Do not overwrite or delete published checkpoints, rewrite history, or force-push.
- For revised artifacts, add new files under the new checkpoint, and describe which earlier findings they supersede.
- Record evidence, confidence, emulator stubs and remaining limits. Never equate function counts with a percentage of complete understanding.
- Retrospective checkpoints must say so; do not fabricate earlier execution or commit timestamps.
- Do not flash firmware, access printer settings, or create service marker files as part of this research.
- Exclude credentials, account contact details, unrelated PC files, caches and native dependencies.
